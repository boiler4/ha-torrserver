# TorrServer для Home Assistant

[English](README.md) · [Italiano](README.it.md) · [Русский](README.ru.md)

Локальная интеграция только для чтения, которая переносит статистику
[YouROK/TorrServer](https://github.com/YouROK/TorrServer) в Home Assistant. Она
не добавляет, не удаляет, не останавливает и не изменяет торренты или настройки.

Текущая стабильная версия — `0.3.0`.

## Возможности

- Рекомендуемый автоматический поиск или ручной URL.
- Basic Auth, HTTPS и самоподписанные сертификаты.
- Скорости, средняя скорость потока с учётом кэша, битрейт, активные торренты и
  воспроизведения, пиры, сиды, кэш и подробная диагностика.
- Здоровье потока: `protected` (Хорошо), `stable` (Стабильно),
  `insufficient` (Недостаточно), `measuring`, `idle`, `unknown`.
- Настраиваемые секунды буфера, границы, запасы скорости и задержка ухудшения.
- Необязательный экспериментальный точный битрейт через `/ffp` TorrServer.
- Интерфейс на русском, английском и итальянском; Diagnostics, System Health и Repairs.

## Установка через HACS

Пока репозиторий не добавлен в стандартный каталог:

1. Откройте HACS → меню → **Custom repositories**.
2. Добавьте `https://github.com/boiler4/ha-torrserver` как **Integration**.
3. Установите TorrServer, перезапустите Home Assistant и добавьте интеграцию в
   **Settings → Devices & services**.

Стабильная версия выбирается автоматически. До одобрения в стандартном каталоге
репозиторий можно установить через HACS как пользовательский репозиторий.

## Поиск и авторизация

Поиск выполняется только по запросу пользователя. Проверяются активные локальные
сети IPv4: максимум 512 адресов и только локальная `/24` для больших сетей.
Используются лишь 8090/HTTP и 8091/HTTPS либо один выбранный порт. Фонового
периодического сканирования нет.

Во время поиска логин и пароль не отправляются. Ответ 401/403 помечает сервер
как защищённый; данные отправятся только после выбора этого адреса. Не используйте
Basic Auth через HTTP в недоверенной сети. Проверку SSL можно явно отключить для
доверенного сервера с самоподписанным сертификатом.

## Оценка здоровья потока

Учитываются только торренты с активным reader кэша TorrServer. Раздаваемый без
просмотра торрент не ухудшает индикатор. При нескольких потоках показывается
худшее состояние, а атрибуты содержат отдельные счётчики.

Главный сигнал — секунды данных перед активной позицией reader. Интеграция
считает последовательные `/cache` `Pieces` с признаком `Completed` до первого
пропуска и переводит их в секунды по битрейту. Текущий кусок исключается, потому
что TorrServer не сообщает точное смещение reader внутри него:

- **Хорошо** (техническое состояние `protected`) — не менее 60 последовательных
  секунд или загруженный файл;
- **Стабильно** — не менее 15 секунд либо малый буфер способен восстановиться;
- **Недостаточно** — менее 15 секунд, а скорость и тренд не поддерживают поток;
- **Измерение** — данных пока недостаточно.

Режим буфера указывается отдельно: `full`, `preloading`, `stable`, `draining`,
`recovering` или `unknown`. `full` означает, что последовательный буфер достиг
порога Хорошо; заполнение кэша остаётся только диагностикой и само по себе не
даёт состояние Хорошо. По умолчанию границы равны 15/60 секундам, запасы
скорости 0%/10%, окно 15 секунд и задержка ухудшения 15 секунд. Все значения
настраиваются. При запасе не более 5 секунд или отсутствии источников ухудшение
применяется немедленно.

Атрибуты содержат секунды, режим и тренд буфера, скорость Mbps, битрейт, границы,
заполнение кэша, число последовательных завершённых кусков, отсчёты, пиры,
сиды, причину и ожидающий переход.

## Экспериментальный битрейт и `ffprobe`

Функция выключена по умолчанию. Home Assistant вызывает существующий endpoint
TorrServer `/ffp` не более одного раза на файл, с тайм-аутом и кэшем только в
памяти. Настройки TorrServer не меняются. При ошибке применяется консервативная
оценка и создаётся предупреждение Repairs.

TorrServer должен иметь возможность запустить `ffprobe`. В проверенной системе
Debian/Linux:

```bash
sudo apt update
sudo apt install ffmpeg
command -v ffprobe
sudo ln -s /usr/bin/ffprobe /opt/torrserver/ffprobe
```

Сначала проверьте реальные пути и не перезаписывайте файлы. Для Docker нужен
образ с ffprobe, для Windows — `ffprobe.exe`, в macOS его обычно предоставляет
пакет ffmpeg. Интеграция никогда не выполняет эти административные действия.

## Ошибки и конфиденциальность

Скачайте **Diagnostics** на странице интеграции, проверьте JSON и вручную
приложите его к форме **New issue**. Логин, пароль, хэши, названия, пути, постеры
и данные файлов скрываются; автоматической отправки нет. Форма запрашивает язык,
версию, шаги воспроизведения, ожидаемый результат и журналы.
